# Wallet Security Checklist

A practical security checklist for anyone holding crypto in a self-custody wallet. Work through it once, then revisit it whenever something feels off.

> Wallet-agnostic. Applies to any non-custodial wallet, including [GitWallet](https://gitwallet.net).

## 🔑 Keys & recovery phrase
- [ ] My seed phrase is backed up **offline** (paper/metal), in the right **order** — see the [backup guide](https://github.com/git-wallet/seed-phrase-backup-guide).
- [ ] No photo, screenshot, cloud file or chat ever contains my seed phrase.
- [ ] I have **more than one** copy, in separate places.
- [ ] I never type my seed phrase into a website — only my wallet's restore screen.

## 📱 Device
- [ ] My phone has a screen lock (PIN/biometrics) and auto-lock.
- [ ] The OS and wallet app are **up to date**.
- [ ] I installed the app only from an **official source** (gitwallet.net / APKPure), not a random link.
- [ ] No sketchy "wallet helper" apps, keyboards or screen recorders are installed.

## 🎣 Phishing & scams
- [ ] I assume anyone asking for my seed phrase or private key is a **scammer** — always.
- [ ] I don't click wallet/airdrop links from DMs, comments or emails.
- [ ] I verify URLs character by character before connecting a wallet.
- [ ] "Support" that DMs me first is fake.

## ✍️ Transactions
- [ ] I **check the recipient address** carefully (first *and* last characters), ideally via QR.
- [ ] I use address safety checks / scam warnings when available.
- [ ] I understand the amount, network and fee **before** signing.
- [ ] I send a small **test amount** first for large or new transfers.

## 🔌 dApps & token approvals
- [ ] I only connect to dApps I trust.
- [ ] I review **token approvals** and avoid unlimited allowances when possible.
- [ ] I periodically **revoke** approvals I no longer use.
- [ ] I disconnect from dApps when finished.

## 🧯 If something goes wrong
- [ ] I know that a compromised seed phrase means I must **move funds to a new wallet** (new phrase) immediately.
- [ ] I report security issues responsibly, not publicly, when a vulnerability is involved.
